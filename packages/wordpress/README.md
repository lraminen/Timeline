# @chronicle/wordpress

The **Chronicle Timeline** WordPress plugin: a `chronicle/timeline` block, a `[chronicle]` shortcode, server-rendered no-JS fallback, caching with a stale copy for outages, and optional post → timeline sync. User-facing documentation is in [`plugin/readme.txt`](plugin/readme.txt) (the wordpress.org format).

Requires WordPress ≥ 6.6 and PHP ≥ 7.4. Both ends of that range are tested.

## Layout

```
plugin/                    the plugin itself; zipped as chronicle-timeline/
  chronicle-timeline.php   bootstrap (header, constants, includes)
  includes/                one class per concern (see below)
  blocks/timeline/block.json
  assets/                  front-end and editor CSS
  build/                   generated by `pnpm build` (git-ignored)
  readme.txt, uninstall.php
src/                       block editor script (TypeScript + React, built to plugin/build/editor.js)
tests/php/                 PHP tests, run inside WordPress Playground
e2e/                       Playwright: real WordPress + real Chronicle server
scripts/                   build, PHP test runner, Playground server, zip packaging
```

| Class                                     | Does                                                                                                                                                                                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Chronicle_Timeline_Urls`                 | Parses timeline links (`/timeline/{slug}[/v/{n}]`, `/api/v1/embed/…`); refuses share links. Mirrored by `src/url.ts`.                                                                                                                  |
| `Chronicle_Timeline_Settings`             | The `chronicle_timeline_settings` option and its validation. `CHRONICLE_TIMELINE_API_KEY` in wp-config.php overrides the stored key.                                                                                                   |
| `Chronicle_Timeline_Client`               | HTTP to Chronicle. The configured server is _trusted_ (may be internal, gets the API key); any other server is fetched with `wp_safe_remote_request`, https only, never with the key. The embed call never sends the key.              |
| `Chronicle_Timeline_Renderer`             | Fetch + cache (fresh for `cache_minutes`, pinned versions a day, last good copy a week, failures remembered a minute) and render: `<chronicle-timeline>` + inert JSON (`JSON_HEX_TAG`) + the server's fallback list through `wp_kses`. |
| `Chronicle_Timeline_Assets`               | The bundled web component (default) or a version-pinned CDN copy with SRI and bundled fallback; loads the component into the block editor's iframe.                                                                                    |
| `Chronicle_Timeline_Block` / `_Shortcode` | Dynamic block (rendered by PHP, so new Chronicle versions appear without re-saving) and the shortcode; both call the renderer.                                                                                                         |
| `Chronicle_Timeline_Rest`                 | `chronicle/v1/timelines` and `chronicle/v1/preview` for the editor (`edit_posts`); the API key stays on the server.                                                                                                                    |
| `Chronicle_Timeline_Sync`                 | Post → event sync, sent at `shutdown`, skipped when unchanged, retried by WP-Cron (5/10/20/40 min) for network and 5xx errors.                                                                                                         |
| `Chronicle_Timeline_Admin`                | Settings → Chronicle.                                                                                                                                                                                                                  |

The plugin fetches `GET /api/v1/embed/{slug}?include=fallback` from the Chronicle server, which adds `fallbackHtml` (the same event list the server's own pages use) and `pageUrl`.

## Commands

```bash
pnpm build          # block script + copies the web component into plugin/build
pnpm test           # Vitest (src/url.ts) + PHP tests on PHP 8.3/WP 7.1 and PHP 7.4/WP 6.6
pnpm test:php 8.3   # PHP tests on one combination only
pnpm test:e2e       # Playwright (needs `pnpm build` of this package and @chronicle/server)
pnpm package        # dist/chronicle-timeline-<version>.zip
pnpm playground     # WordPress on http://127.0.0.1:9400 with the plugin active (admin / password)
```

No PHP, MySQL or Docker is needed: [WordPress Playground](https://wordpress.github.io/wordpress-playground/) runs WordPress on PHP compiled to WebAssembly, with SQLite. The first run downloads WordPress; unpacked sites are kept in `.playground/` (git-ignored) and get a fresh database on every run.

The PHP tests use a small harness (`tests/php/harness.php`) instead of WordPress's PHPUnit suite, which needs MySQL and a wordpress-develop checkout. All HTTP is intercepted with `pre_http_request`.

To try it by hand against a local Chronicle server: run the server (`pnpm --filter @chronicle/server dev`), create an API key in the editor (Account menu → API keys…), run `pnpm playground`, and enter the server URL and key under Settings → Chronicle.

## Before submitting to wordpress.org

- Run the official [Plugin Check](https://wordpress.org/plugins/plugin-check/) on the zip (`wp plugin check chronicle-timeline`).
- Replace `Contributors: chronicle` in `readme.txt` with real wordpress.org usernames.
- `build/chronicle-timeline.js` is minified; add a link to its public source repository in `readme.txt` (wordpress.org requires access to the human-readable source). `build/editor.js` is shipped unminified.
- Version numbers: `pnpm package` refuses to build unless the plugin header, `CHRONICLE_TIMELINE_VERSION`, the readme's `Stable tag` and `package.json` agree.
